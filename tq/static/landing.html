How it works

Watch it run. Then decide.

A tool's description is a promise. Tool Quarantine checks the promise in under a minute.

01QuarantineFresh container: no internet route, read-only disk, every capability dropped, decoy credentials planted.
02ExerciseAn agent on Vultr Serverless Inference reads the tool's own description and calls it with realistic inputs.
03Observestrace records every file and process; a sinkhole answers DNS and HTTP and keeps whatever the tool tries to send.
04DecideClaims vs. reality, a trust score, your workspace policy, and a one-click approve or block. Then the box is destroyed.
Product

Everything between “found it on GitHub” and “my agent uses it”.

Built for platform and security teams that let agents pick up third-party tools.

◉

Live detonation

Watch file reads, credential access, DNS lookups and outbound POSTs stream in while the tool runs, then replay the run for your team.

⇆

Claims vs. reality

Every area the tool's description mentions or denies (files, secrets, network, processes, writes) next to what it actually touched.

#

Code-pinned registry

Approvals attach to the sha256 of the code. Change one byte and the tool is unknown again, so a later “update” can't slip in a rug pull.

⚖

Policies

Auto-block exfiltration, credential theft and tool poisoning. Require a written reason for anything borderline. Expire approvals.

⌁

Gateway & CI checks

One HTTP call tells an MCP gateway, agent runtime or CI job whether this exact code may run.

▤

Audit trail

Who approved what, when, and why, for every version. Export any report as JSON or PDF.
